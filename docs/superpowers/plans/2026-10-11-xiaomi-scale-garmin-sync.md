# Xiaomi Scale → Garmin (Android) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** An open-source Android app that captures Xiaomi Smart Scale S200 weigh-ins in the foreground, archives them locally with review/cleanup controls, and pushes them to Garmin Connect without duplicates.

**Architecture:** Single-module Kotlin app. A pure-Kotlin protocol stack (crypto → MIoT codec → framing → session) runs over a `BleTransport` interface with two implementations: a real Android GATT transport and an in-memory `FakeScale` test double, so the whole sync engine is proven on the JVM before any hardware touches it. A `SyncEngine` implements the reference client's connection discipline; repositories own the archive (Room) and the Garmin push queue.

**Tech Stack:** Kotlin, Jetpack Compose (Material 3), Coroutines/Flow, Room, OkHttp, Android Keystore, WorkManager, JUnit4 (JVM), MockWebServer, Gradle/AGP (versions are the builder's call; minSdk 26, target latest).

**Spec:** `docs/superpowers/specs/2026-10-11-xiaomi-scale-garmin-sync-design.md` — the plan argues from the spec; executors read both. Protocol byte-level facts live in the spec and in the reference repo README (https://github.com/faraga1/xiaomi-scale-s200-ble).

**Out of scope for this plan:** the v2 companion web server (separate later plan), Play Store publishing, iOS.

## Global Constraints

- Connect discipline: connect **only** after handling a `0x4e16` weigh-in broadcast or when frame-control bit 9 (`0x0200`) is set. Max 1 attempt per 600 s; max 2 attempts per sync; failed/fruitless solicited sync mutes solicits for 10_800_000 ms (3 h). Never connect on mere visibility or on the ~50-min status object `0x6623`. No background service, ever; no timers that connect.
- Timeouts/backoff: step 4_000 ms, result 6_000 ms, records 8_000 ms; live listen start 5_000 ms / idle 15_000 ms / max 600_000 ms; failed-sync backoff 60_000 ms doubling to max 1_800_000 ms; awake re-check cadence 300 ms; silence banner at 12 h of app-open listening.
- Never automatically call action **6.2** (delete) or **4.3** (claim). 6.2 only via the explicit Scale-cleanup UI. 4.3 never.
- Dedupe key = (recordedAt unix second, weightGrams). Weight accepted 100–30000 g (1–300 kg); timestamps < 1_704_067_200 or > now+300 s → replace with receive time.
- Categorization: flag 0 + member id match → `MINE`; flag 2 / mid 0 → `NEEDS_REVIEW`; `GUEST` only via explicit "keep as guest". Non-`MINE` records never push. Approval flips to `MINE` and becomes pushable.
- Backfill: records with `recordedAt` < app install time archive as `garminStatus = SKIPPED_EXISTING`, never pushed.
- Duplicate guard: before **every** Garmin push, fetch that day's Garmin weigh-ins; skip when an entry matches the same timestamp (fallback: same calendar date + same value).
- Garmin payload: `{"dateTimestamp": <local "yyyy-MM-dd'T'HH:mm:ss.SSS">, "gmtTimestamp": <UTC same format>, "unitKey": "kg", "sourceType": "MANUAL", "value": <kg, decimal>}`. Retry 5xx/network only (3 attempts, 1–10 s exponential + jitter); never retry 401/429.
- Profile push JSON (exact key order): `{"mid":"<member id>","duid":1,"uc":1,"ow":1,"unit":1,"time":<unix now>,"ud":[{"duid":1,"ut":1,"age":<age>,"sex":<sex>,"hi":<height cm>,"wt":<latest weight g or 8000>}]}` — mid default `"1"`, `unit` always `1` (kg).
- Stored-records string: records joined by `_`, each `no,mid,user_type,weight_g,flag,unix_ts` (e.g. `41,1,1,8025,0,1790000000_42,0,0,7260,2,1790000060`).
- Keys: TOKEN 24 hex chars (12 bytes), BLE KEY 32 hex (16 bytes), MAC. BLE KEY is required to finish onboarding (manual paste validates both). Keys/tokens never logged, stored only in Android Keystore-backed storage.
- Permissions: `BLUETOOTH_SCAN` with `neverForLocation` + `BLUETOOTH_CONNECT` (API 31+); legacy `ACCESS_FINE_LOCATION` + old Bluetooth perms below 31. No foreground service types declared for scanning.
- License MIT; package/app id `com.xiaomiscalesync`.

## Review Focus

Inputs/conditions the spec implies but that no happy-path test naturally covers. Each is pinned to the task that owns it.

1. **CCM nonce/AAD layout differs between broadcast path (MAC_le + product + counter + ext, AAD `0x11`) and session path (iv + 00000000 + ctr, no AAD)** — a mix-up silently breaks both. → Beacon vectors in Task 7 and session encrypted round-trip in Task 6 both assert on pinned ciphertext/nonce layouts generated by `scripts/gen_vectors.py`.
2. **Framed transfers ack once before and once after all parcels, never per parcel; a lost/late parcel must not deadlock the session.** → Task 4 framing tests include a 2-parcel 6.1 payload through `FakeScale` asserting exact ack order and the `recv` reassembly, plus a timeout path.
3. **Login stalls if notifications are enabled out of order or without the ~200 ms pause (reference: ~57% login failure).** → `FakeScale` rejects `24000000` unless AUTH/CMD/PROP are notified, probe completed, pause elapsed, then LOGIN notified; Task 5 asserts the session passes and a deliberately misordered session fails.
4. **Connect-discipline violation (battery drain / stuck scale).** → Task 9 fake-clock tests assert zero connects for visibility-only and status-only advertisements, the 600 s interval cap, the 2-attempt cap, backoff, and that 6.2 is never written outside the explicit cleanup API.
5. **Duplicates into Garmin (both pipelines live) and guest leakage into Garmin.** → Task 12 fixture tests for the same-timestamp/same-day-value guard and auth flip; Task 8 tests for backfill cutoff and that `pending()` never returns `NEEDS_REVIEW`/`GUEST` records.
